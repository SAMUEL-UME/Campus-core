## Maintenance and priorities
Read relevant requirements before implementation; update authoritative files alongside meaningful changes. Task board alone owns task statuses. Record decision approval and supersession without deleting history. Audit findings and implementation evidence reference controls rather than redefining them. Never convert planned controls into passes.

Foundation documents are current priorities. Add a research evidence log when interviews occur, not fabricated findings. Before public launch add deployment guide, release checklist and operations/incident/restore runbook. Before tracking or revenue features add analytics/monetization strategy and privacy review. Neither is MVP-approved. API/auth design stays in architecture until complexity warrants separate documents. No duplicate overview/user-story file or CLAUDE.md is needed; any future Claude compatibility file should point to AGENTS.md.
