# Campus Core — SEO Strategy

**Version:** 0.1 | **Status:** Proposed, before public deployment | **Owner:** Samuel with Chidera

## 1. Objectives
Make authorized public departmental information discoverable without indexing private student data, draft content, restricted materials, or administrative screens. SEO supports the long-term product, but does not outrank accuracy, permissions, or MVP delivery.

November 3 P0 exception: fictional demonstration pages must be visibly labeled and noindex; do not place fictional items in public sitemaps or Event structured data. Descriptive page metadata and semantic navigation still apply. Before enabling indexing on a real release, review permissions/canonical origin and replace this demo-only policy explicitly. Robots/noindex is not a security boundary.

## 2. Public information architecture (proposed)
```text
/
/universities/unizik
/universities/unizik/departments/computer-science
/universities/unizik/departments/computer-science/announcements
/universities/unizik/departments/computer-science/announcements/[slug]
/universities/unizik/departments/computer-science/resources
/universities/unizik/departments/computer-science/events
```
Routes are examples, not implemented or approved. Preserve stable slugs and canonical paths. Academic level filtering can use query parameters with canonical rules to avoid duplicate pages.

## 3. Technical requirements
- Unique descriptive `<title>` and meta description for indexable pages.
- Canonical URLs and stable readable paths.
- XML sitemap containing only approved public canonical URLs.
- `robots.txt` guidance plus actual authentication/authorization; robots rules are **not** access control.
- `noindex` for search/filter variants when appropriate, and for sign-in or private routes; never rely on `noindex` to secure confidential data.
- Structured data only when accurate and supported (e.g., organization/site breadcrumbs or real events); never fabricate reviews or official affiliation.
- Open Graph metadata and sensible sharing previews.
- Mobile performance, accessible headings, semantic links, image alt text, and Core Web Vitals monitoring.

## 4. Content quality
Show original source, publisher identity/role, publication and update dates, relevance, and expiry. Avoid thin autogenerated university pages, misleading exam notices, duplicate copied materials, and unlicensed PDFs. Update or withdraw outdated content promptly.

## 5. Indexing rules
| Content | Index? | Reason |
|---|---|---|
| Public approved university/department landing pages | Yes, after approval | Discovery |
| Public published announcement detail | Conditional | Permission, relevance, freshness |
| Public curated resource listing | Conditional | Permission and useful unique content |
| Public event details | Conditional | Accurate event information |
| Draft, withdrawn, restricted content | No; must be access-controlled | Confidentiality/integrity |
| Admin, account, moderation, profile | No; must be access-controlled | Privacy |
| Internal search and personalized filters | Generally no | Duplicate/low-value pages |

## 6. Implementation checklist
1. Approve route taxonomy and indexable content policy.
2. Implement Next.js metadata and canonical URLs.
3. Generate sitemap from published authorized records only.
4. Configure robots/noindex where relevant.
5. Test public versus private routes and removed-content behavior.
6. Validate structured data, mobile layout, and link accessibility.
7. After approved launch, configure appropriate search performance monitoring with privacy review.

## 7. Metrics and governance
Track indexed valid pages, search impressions/clicks, broken URLs, page performance, and stale-content incidents only after approved measurement setup. Chidera owns content messaging; Samuel owns technical SEO; Adimchi owns accuracy and permission policy.
