## 3. Working cadence
- Short planning check-in at sprint start; one shared task board with owner, status, acceptance criteria and dependencies.
- Daily asynchronous blocker updates during hackathon build where practical.
- Demo working functionality at milestone end; QA records defects before closure.
- Decisions affecting scope, data, security or cost recorded in a decision log.
- Never assume progress when a team member has not reported it.

## 5. Definition of done
Feature meets acceptance criteria; relevant checks actually run; security/permissions reviewed; mobile/accessibility tested where applicable; documentation updated; owner and reviewer acknowledge completion.

## 6. Escalation
Blockers that affect hackathon deadline, content authorization, privileged access, cost, or data privacy go to Samuel promptly. Scope cuts must be explicit and documented.
